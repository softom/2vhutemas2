# API проекта

API проектируется с первой версии. Веб-интерфейс, Telegram-бот и навык наполнения используют общие прикладные операции и правила доступа. Эта спецификация не означает, что маршруты уже работают. Не заменяет действующий legacy API.

## Контракт и доступ

- Предлагаемый префикс `/api/v1`. До реализации маршруты ниже считаются проектными.
- Перед реализацией оформить OpenAPI с типами запросов/ответов, схемой блоков, перечислениями, примерами и ошибками. Опубликовать машинно читаемый контракт и номер версии схемы.
- Аутентификация через существующую систему аккаунтов. Для автоматизации — отзываемый ограниченный токен с областью действий; формат и механизм выдачи реализовать отдельно. Секреты не хранятся в навыке или документации.
- Разрешения view/edit/create_delete/su проверяются для ресурса и видимости. Аккаунт автоматизации не получает роль администратора по умолчанию. Сохраняются исполнитель и происхождение импортированного материала; импортёр не становится автором произведения.
- Для изменений — base_revision_id или If-Match; конфликт возвращает 409/412 без затирания правок. POST с повторяемым действием поддерживает Idempotency-Key; повтор с тем же ключом и другим телом отклоняется.
- Списки используют курсорную пагинацию и документированные пределы. Ошибка: code, message, details, request_id без секретов. Различаются ошибки проверки, отсутствие доступа, конфликт, ограничения и временный сбой.

## Стартовые операции

| Маршрут (проект) | Назначение |
|---|---|
| GET /capabilities | Версия контракта, поддерживаемые типы и лимиты |
| GET /entities; GET /entities/{id} | Поиск/фильтры, карточка сущности |
| POST /entities; PATCH /entities/{id} | Создание и новая версия свойств/профиля |
| POST /links | Атомарно создать связь вместе с описанием и прикреплением justification |
| GET /entities/{id}/links | Окружение объекта с обоснованиями |
| GET /articles; GET /articles/{id} | Каталог и чтение самостоятельных статей |
| POST /articles; PATCH /articles/{id} | Метаданные и BlockNote-документ с индексом ссылок |
| GET /entities/{id}/articles | Доступные статьи, содержащие объект |
| GET /materials/{id}/revisions | История и сравнение версий |
| POST /materials/{id}/restore | Создать новую версию на основе выбранной старой |
| DELETE /materials/{id} | Архивирование, требующее create_delete, с сохранением истории |
| POST /media | Загрузка оригинала в общий медиаконтур |
| GET /media/{id} | Метаданные, готовность и разрешённые ссылки на варианты |
| GET /search | Поиск объектов, статей и доступных фрагментов |
| GET /me | Аккаунт, состояние подтверждения и эффективные права |
| POST /account-links/telegram/confirm | Подтверждение адресного одноразового кода сервером бота |
| GET /users; GET /roles; PATCH /users/{id}/roles | Управление пользователями и правами с отдельным административным доступом |
| POST /imports/validate | Проверка пакета без записи, поиск возможных дублей |
| POST /imports; GET /imports/{id} | Запуск и состояние пакетного наполнения |

Выдачу файлов согласовать с существующим `/api/media`; новая таблица маршрутов не требует немедленной смены его адресов. Публикация — отдельная операция после определения её политики; edit/create_delete не означают автоматическую публичную публикацию.

## Пакетное наполнение

Пакет содержит manifest_version, источник, внешний ключ каждой записи, локальные ключи зависимостей, сущности, связи с обоснованиями, медиа и статьи. Формат BlockNote проверяется по актуальной схеме, неизвестные блоки не отбрасываются. Время, авторство, источники и интерпретации не додумываются при импорте.

Сначала validate: возвращает ошибки, совпадения и план create/update/skip. Затем apply использует проверенную версию пакета; при изменении данных повторно проверяются конфликты. Неоднозначные совпадения не объединяются автоматически по названию или slug.

Идентичность импорта задаётся `(source_namespace, external_key)`, а не slug. Импорт сохраняет таблицу соответствий ключей и ID; её ограничение уникальности защищает от дублей при повторном запуске. Миграционный legacy_id_map может использовать тот же принцип, но не подменяется без проверки.

Границы атомарности: одна сущность с профилем, одна связь с обоснованием, одна версия статьи с индексом ссылок. Весь большой пакет не обязан быть одной транзакцией. Ошибки зависимостей блокируют зависимые элементы, успешные сохраняются и отражаются в отчёте. Повтор продолжает пакет без дублирования.

Файлы загружаются отдельно; отчёт отслеживает готовность original/screen/thumbnail. Автоматизация передаёт файл, а не произвольный URL для неконтролируемого скачивания сервером. При будущем серверном импорте URL нужны ограничения адресов, размеров и форматов.

До реализации спроектировать import_jobs, import_items и import_key_map: исполнитель, ключ идемпотентности, hash пакета, состояние, локальный/внешний ключ, полученный ID, ошибка, попытки и время. Операционные журналы не смешиваются с авторством материалов.

## Навык наполнения

Исходник навыка: [SKILL.md](../skills/2vhutemas-content/SKILL.md). Пока API не реализован, навык готовит и проверяет локальный план наполнения; он не выдаёт этот план за запись в БД. После реализации контракта добавить клиент и проверить наполнение на тестовом окружении.

Приёмка: повтор того же пакета не создаёт дублей; связь без обоснования отклоняется; конфликты не затирают пользовательские правки; права и приватность одинаковы для интерфейса и API; частичный сбой даёт воспроизводимый отчёт; лекция содержит реальные ссылки на созданные сущности.

Настройки и лимиты: [Параметры проекта](Параметры%20проекта.md). Перед реализацией применить правила UID из [Правил проекта](Правила%20проекта.md); коды разрешений не являются FK.
