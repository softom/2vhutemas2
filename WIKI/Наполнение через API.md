# Наполнение через API

Как сессия ассистента записывает тексты и сведения в базу через API сайта, не вынося секреты с сервера.

## Кто пишет

Участник **«Сессия наполнения»** (`app.contributors`, роль `editor`: view, edit, create_delete, publish, review). Его записи видны в истории версий под этим именем.

## Порядок

1. Данные (JSON с `body_json`, показателями и т. п.) готовятся локально и копируются на сервер во временный файл.
2. **Токен выпускается на сервере** на секрете подписи API (`JWT_SECRET` из `/opt/2vhutemas-services/app-api/.env`): HS256, `sub` — `auth_uid` участника, `role`/`aud` — `authenticated`, срок — 10 минут. Секрет и токен не выводятся, не попадают в файлы проекта и в переписку.
3. С сервера: `GET /entities/{id}` → `latest_revision_id`; `PATCH /entities/{id}` с `base_revision_id`; `POST /entities/{id}/publish` с полученным `revision_id`.
4. Временные файлы и переменная с токеном удаляются в том же запуске.
5. Проверка — гостевым чтением `GET /entities/{id}`: опубликованная версия и текст на месте.

Порядок требует подтверждения пользователя: это работа с секретом подписи боевого сервера.

## Карточка и лекция

*Правило пользователя 2026-10-02.* **Описание объекта — только в карточке, в лекции не дублируется. Лекция — рассказ о том, почему придумали делать именно так:** какая задача, почему она стала решаема именно тогда, на чей прежний опыт опирается решение, чем за него заплатили. Отсылок к порядку чтения («второй ход», «на прошлом занятии») нет: материал читают разные люди и подряд.
