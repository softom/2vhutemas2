# Каталог: потерянное нажатие «Показать ещё» — 16.11.2026

Пользователь сообщил: кнопка «Ещё» вызывает ожидание 10–15 секунд, список остаётся на 24 записях.

Воспроизведено чистым Chromium на публичном /objects: кнопка видна на 3,99 с, нажата, спустя 30 секунд по-прежнему 24 записи. Запрос с cursor не отправлен вообще. Первый GET /entities?scope=objects&type=what&order=asc пришёл только на 25,75 с; stat.2vhutemas.ru/script.js завершился тайм-аутом. Серверный listCountHtml рисует активную кнопку без обработчика. До запуска React нажатие теряется. Дополнительно script аналитики стоит defer перед модулем приложения.

План/подготовленное исправление: аналитика async; серверная кнопка сразу сохраняет намерение загрузить ещё и показывает «Подключаем каталог…»; клиент после первой страницы с действующими правами выполняет сохранённый запрос по её cursor. Пока первоначальный список обновляется, кнопки React отключены, чтобы обновление не затёрло добавленную страницу. Проверить с задержкой приложения/аналитики, ранним нажатием и последовательной пагинацией без дублей. Выкладка пока не выполнена. Общие файлы исследования эскиза не меняются.
Проверено на общей production-сборке: Deno check, TypeScript и Vite проходят. Chromium-регрессия tools/test_catalog_more_browser.py задерживает подключение приложения на 2 секунды, аналитику на 8 секунд: раннее нажатие сохранено, последовательность 24 → 48 → 51, все 51 карточки уникальны, ошибок JavaScript нет. Запрос каталога начинается примерно на 3-й секунде, до завершения аналитики. Селектор SSR ограничен button[data-catalog-more], чтобы не затронуть HTML-элемент с маркером очереди.

Изменения готовы для единого выпуска с публикацией медиа ca08a66 и исследованием 7a41e96. Выкладку выполняет согласованная параллельная сессия; эта запись пока не подтверждает выпуск на production.
