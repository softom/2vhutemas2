# Инвентаризация страниц, секций, виджетов и мини-игр

19.11.2026. Этап 1 [[Этапы реализации — виджеты]]. Основания: дерево проекта на 4bcd1e6, выборка PostgreSQL в транзакции READ ONLY и внешние гостевые HTTP GET с переходом по перенаправлениям. В приложении [JSON настроек](Инвентаризация%20виджетов%20—%20настройки%20карточек.json) сохранены все 12 явных представлений card с элементами, порядком и UID, а также UID и стороны всех 25 наборов. Выгрузка отражает момент проверки.

## Фактические настройки и наследование

Общая последовательность: indicators → links → program → text → gallery → drawings → sources → mentions → citation. Её явно используют what, who, when, where, service, materials, project_pages. У article, book и web_page тот же порядок без sources. У image только indicators → text → mentions → citation. У video после indicators вставлен video, отдельной секции sources нет. Это именно строки представлений типов; потомки без своих строк получают ближайшее представление через app.presentation_for. При рендеринге parameter_sets дополнительно вставляется перед text, если отсутствует в списке.

У всех 12 представлений settings = {}. Размещений в settings.card_widgets в этом снимке нет. Два набора слева: style_solutions и area_program. Остальные 23 справа. Встроенные секции используют сторону при разборе значений и наборов. При инвентаризации новых макетов следует учитывать и неявно вставляемую секцию.

## Состав карточки

| Встроенная секция cardBody | Источник и поведение |
|---|---|
| indicators | card.values справа, группы по индикатору, обычные значения, даты, места и таблицы. У новости специальный состав сведений. Сюда также могут попасть правые наборы связей и площадная программа. |
| parameter_sets | Левые значения card.values и соответствующие наборы связей. Встроенный вывод параметров; определения виджета params нет. |
| links | card.links и neighbor_links: граф и список, роли и обоснования |
| program | Специализированное представление площадной программы, строки и итоги с учётом стороны |
| video | Адрес ролика, канал, длительность, собственная обложка или превью |
| text | Подготовленный HTML Мультитекста, у новости без подзаголовка «Описание» |
| gallery | Иллюстрации из card.media с подписями и источниками |
| drawings | card.drawings: просмотр чертежа, измерения, скачивание и подписи |
| sources | Источники, внутренние и внешние ссылки, обстоятельства цитирования |
| mentions | Упоминания в других материалах со ссылками на владельца |
| citation | ГОСТ, APA, постоянный адрес и копирование |

Вне этого списка cardBody формирует заголовок, альтернативные названия, метаданные и теги, а у новости — навигацию и блок «Ещё за этот день». При переданном редакторском контексте добавляет материалы в работе. Эти элементы следует проверять отдельно при замене композиции.

**Дополнительный виджет в реестре один — style_analysis.** В api/src/lib/cardWidgets.ts он связан со styleAnalysis. Реализация выбирает style_solutions из card.relation_sets и показывает атрибуции, поля и цитаты. В текущем коде поиск набора выполняется по code; это точка сверки с требованием связей по UID. При выводе виджета соответствующий набор исключается из встроенной панели, иначе действует встроенный вывод. Регистрация функции сама по себе не означает назначения типа. При существующем наборе без связей реализация может вернуть заголовок и сообщение — отдельный случай для проверки целевого правила пустого слота.

## Игра и модели

В web/public/games одна игра: «Стили». Рабочий публичный адрес **/games/stili.html** проверен (200); адрес /game/styles из плана проверен (404). Генератор tools/make_game_stili.py связывает 34 здания с 17 стилями, хранит годы и признак начала строительства либо открытия. Шаблон tools/game_stili.tpl.html запрашивает сведения о здании по UID. Игрок выбирает стиль; правильный или предусмотренный альтернативный ответ даёт одно очко, ошибки попадают в итог, повтор сбрасывает партию. При переносе сохранить подбор, слайды и подписи, пояснения к ответам, порядок раундов, итог и старый рабочий URL. Авторство персонально из этих файлов не установлено.

## Граница проверки

Инвентаризация фиксирует исходное состояние до изменений. HTTP-проверки подтверждают доступность перечисленных адресов, без проверки каждой игровой партии и экранов под редакторской учётной записью. Контрольные HTML и пары скриншотов гостя/редактора (1.5), резервная копия и проверка восстановления (1.6) остаются самостоятельными работами этапа. Выгрузка настроек не заменяет резервную копию.
