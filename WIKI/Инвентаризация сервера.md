# Инвентаризация сервера

Первый шаг 1.1 [Плана реализации](План%20реализации.md). Проверка выполнена 2026-09-22 по SSH (хост `2vhutemas`) только чтением: запросы к PostgreSQL в режиме `default_transaction_read_only`, листинги каталогов, выборочные переменные окружения контейнеров без секретов. Изменений на сервере не вносилось.

## Безопасность: найдено

**Критично — legacy `public`.** На таблицах `authors`, `styles`, `phenomena`, `phenomenon_style`, `reference_entries`, `reference_author`, `style_reference`, `project_feature`, `schema_migrations` RLS выключен, а роль `anon` имеет INSERT/UPDATE/DELETE/TRUNCATE. Схема `public` открыта через PostgREST. Значит, владелец публичного anon-ключа (он есть во фронтенде сайта) может изменять и удалять эти данные через REST. Проверка извне записью не выполнялась.

**`v2`.** RLS выключен. `anon` читает все таблицы, включая будущие черновики `documents`; любой `authenticated` может писать. Пока данные — только 23 периода.

**`students`.** Политики `auth_all` (`true`) дают любому вошедшему пользователю полный доступ ко всей ведомости: телефоны, `access_token`, оценки, работы. Схема не открыта в PostgREST, регистрация закрыта, аккаунтов 3 — поэтому сейчас риск ограничен. **Заводить студентов как `authenticated` при этих политиках нельзя** — это прямой блокер этапа 3.

**`public.media_assets`, `projects`, связи.** Политики `*_editor_all` дают любому `authenticated` полный доступ. Приемлемо, пока вошедшие — только администраторы.

Устранение согласовано (решение [Р-05](Архив%20решений.md)). Ход работы — в разделе ниже.

## Исправление прав: ход работы

1. Снята и проверена резервная копия (целостность архива подтверждена, восстановление не проверялось).
2. Проверено, что отзыв прав у `anon` ничего не ломает: `app_media` и `app_timeline` работают через service-ключ; редакторы `arch_object_edit.html`, `style_edit.html`, `epoch_edit.html` пишут после входа, то есть как `authenticated`.
3. Попытка выполнить REVOKE от роли `postgres` не прошла: legacy-таблицы принадлежат `supabase_admin`, гранты выдавал он же, а `postgres` не является ни суперпользователем, ни членом этой роли. Транзакция откатилась, изменений нет.
4. **Выполнено 2026-09-22** от роли `supabase_admin` (пароль читается на сервере из `/opt/2vhutemas/.env`, в WIKI, Git и переписку не попадает):
   - отозваны INSERT/UPDATE/DELETE/TRUNCATE у `anon` на 16 таблицах и 2 представлениях legacy-контура;
   - `ALTER DEFAULT PRIVILEGES` для ролей `postgres` и `supabase_admin`: новые таблицы в `public` больше не получают права записи для `anon`.
5. Проверка после изменения: у `anon` в `public` не осталось прав записи ни на одной таблице проекта; SELECT сохранён на 22 объектах, публичное чтение сайта не затронуто. Права по умолчанию для `anon` теперь `rxtm` — без записи.

Не тронуто намеренно: `public.gis_project` (политика `anon_insert` ГИС-контура) и системные таблицы PostGIS `spatial_ref_sys`, `geometry_columns`, `geography_columns` — у `anon` там остались права записи. Предложение закрыть и их требует отдельного согласования с владельцем ГИС-контура.

Замечание: порты PostgreSQL (5432) и Kong (8000) слушают только 127.0.0.1, наружу смотрит Caddy. Поэтому доступ роли `anon` возможен только через PostgREST, а право TRUNCATE через него не используется.

## Схема `app`: применено 2026-09-22

## API нового контура: запущен 2026-09-22

Сервис `app_api` — контейнер `denoland/deno:alpine-2.1.7` в `/opt/2vhutemas-services`, исходники в `app-api`, порт 127.0.0.1:7073, публичного маршрута пока нет. Работает от роли `app_api`, подключается к `supa_db` в сети Supabase.

Готовые операции: `GET /api/v1/health`, `/capabilities` (версия контракта, лимиты, словари), `/me` (участник и его права), каталог сущностей с фильтрами и курсорной постраничностью, карточка, создание и правка с записью версии.

Проверено сквозным тестом с настоящим токеном Supabase:

| Проверка | Результат |
|---|---|
| Вход по токену, участник заводится при первом входе | без прав, как и задумано |
| Создание без права `create_delete` | отклонено, 403 |
| Создание после выдачи роли `editor` | создано, версия записана |
| Адрес с пробелами и заглавными | отклонено, 400 |
| Правка от устаревшей версии | 409, указана актуальная версия |
| Правка от актуальной версии | принята, вторая версия записана |
| Чтение черновика гостем | 404, черновик не раскрыт |

Тестовые данные удалены, контур пуст.

Две ошибки найдены запуском и исправлены: слой совместимости с Node не разрешает имена контейнеров Docker (драйвер БД заменён на родной для Deno), и `bigint` не сериализуется в JSON (добавлено преобразование без потери точности).

## Правки по итогам первой работы с формой

2026-09-23, после проверки пользователем:

- Поле адреса страницы подписывалось просто «Адрес» — в него вводили почтовый адрес объекта. Подпись уточнена, добавлена подсказка, значение подставляется из названия транслитерацией и остаётся изменяемым.
- Почтового адреса в модели не было: миграция 0007 добавила `app.object_profile.address`, поле появилось в форме и карточке.
- Правка объекта не сохраняла профиль: менялись только общие поля, а город, тип и адрес молча оставались прежними. Исправлено.
- Смена адреса страницы теперь записывает прежнее значение в `app.slug_history` — старые ссылки не ломаются.
- Ошибки проверки показываются у своих полей, а не одной общей строкой.
