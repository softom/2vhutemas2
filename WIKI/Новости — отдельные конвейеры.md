# Новости — отдельные конвейеры

## Указание пользователя, 2026-11-09

Разным потокам новостей нужны разные конвейеры. Для архитектурного проекта известной компании не нужно обучать LLM предпочтениям: нужно собирать выборку и определять новизну. Поток ИИ обильный и не профильный для сайта: требуется сложный отбор с информированием редактора. Конкурсы — отдельный процесс. Ещё один поток — новости по материалам сайта. Дополнительные категории предложить, но не раздувать их число.

Это уточняет общий механизм обучения от 6–7 ноября: оценка предпочтений не должна быть обязательным этапом каждого потока. Существующие оценки и профиль сохраняются. На момент первоначального обсуждения изменений кода, настроек и данных не выполнялось. Последующее поручение о таблице категорий зафиксировано ниже; правила автоматической публикации не меняются.

«Материалы сайта» пока истолкованы как собственные публикации и существенные обновления; пользователь ещё не уточнил, включает ли это поиск внешних новостей по объектам каталога.

Новизна архитектурного проекта — прежде всего новое относительно уже собранного и опубликованного: старый проект в свежем издании не становится новым. Архитектурная оригинальность — отдельный возможный разбор. Известность бюро является основанием наблюдения, не доказательством качества и не разрешением публикации. Новые бюро могут поступать через выбранные источники и ручное добавление.

Исследования и знания охватывают архитектурную науку, материалы и конструкции, историю архитектуры, реставрацию и искусствоведение. Исследования ИИ идут в поток ИИ. Новая ИИ-функция конкретной архитектурной программы идёт в ПО, если главное — изменение работы в этой программе; новый метод или более широкое явление — в ИИ.

## Общие механизмы и границы

- Россия — сквозной географический и редакционный приоритет, не отдельный конвейер.
- Резонанс — дополнительное наблюдение и сбор источников для истории любого потока.
- Интервью, выставки, премии и наследие пока не требуют новых конвейеров: жанр и тема сами по себе недостаточны; неподходящий материал остаётся на ручном разборе.
- Одна история получает основной маршрут; сведения из других потоков дополняют её, не создают автоматически вторую новость.
- Общие части: источники, поиск повторов, связи только по UID, редакторское решение, сохранение авторских правок, аудит, BackUp и публикация.
- Попадание в выборку, информирование редактора и выход на сайт — разные действия. Требования Р-119/Р-121 к публичному выходу этим предложением не отменены.
- Сводка ИИ предлагается внутри пульта редактора; периодичность и внешние уведомления ещё не определены и не включены.
- Уточнение 2026-11-09: пользователь явно поручил отдельную таблицу категорий; прежнее ограничение этой страницы «без новых таблиц» заменено этим решением. Общий числовой рейтинг для всех потоков не вводится.

### Структура app.news_categories

Новая таблица — справочник маршрутов обработки и оформления, не замена entities и не отдельное хранилище текстов новостей.

| Поле | Тип и ограничения | Назначение |
|---|---|---|
| id | uuid, PRIMARY KEY, DEFAULT gen_random_uuid() | Стабильный UID категории; единственное основание внутренних связей |
| title_ru | text, NOT NULL, непустое | Полное название |

| description | text, NOT NULL, непустое | Содержание категории и границы отбора |
| color | text, NOT NULL, CHECK формата #RRGGBB | Цвет пиктограммы и метки |
| icon | text, NOT NULL | Имя пиктограммы из поставляемого с приложением набора Lucide; не HTML, не SVG-код и не внешний URL |
| sort_order | integer, NOT NULL, DEFAULT 0 | Порядок категорий; при равенстве дополнительная сортировка по id |
| is_active | boolean, NOT NULL, DEFAULT true | Доступность для назначения новым новостям; отключение не удаляет старые связи |
| created_at / updated_at | timestamptz, NOT NULL | Время создания и последнего изменения |
| created_by / updated_by | uuid, FK → app.contributors(id) | Участники, выполнившие изменения; при начальном заполнении — исполнитель миграции |

Названия, цвет и имя пиктограммы — изменяемые атрибуты, не ключи связей. Имена пиктограмм проверяются по разрешённому набору на сервере; интерфейс использует локальный общий SVG-набор. UUID начальных шести категорий должны быть зафиксированы в будущей миграции и одинаковы во всех средах; при повторном заполнении UID не генерируются заново. Для начального заполнения без участника допустимость NULL в полях авторства должна быть явно оговорена миграцией, а не подменена вымышленным пользователем.

### Связь с новостью и версии

Проект связи: nullable-колонка app.entities.news_category_id типа uuid, FK → app.news_categories(id), ON DELETE RESTRICT, индекс для выборки. Категория разрешена только записям типа «Новость»; проверка — по UID типа. Одна новость имеет одну основную категорию. Другие записи имеют NULL. На время перехода NULL допустим у старых новостей и не скрывает их из общей ленты; после разбора старых записей категория обязательна для новой публикации новости.

UID категории включается в entity_snapshot и снимки revisions. Публичная выдача и фильтрация читают категорию опубликованной версии: смена категории в рабочем черновике не перемещает опубликованную новость до публикации этой версии. Старые исторические снимки не переписываются. Название, цвет и пиктограмма отображаются по текущей записи справочника — изменение оформления применяется последовательно ко всей ленте.

Старый многозначный параметр news_topic сохраняется вместе со значениями и историей. Новая категория определяет основной маршрут и выдачу; прежние темы не должны оставаться вторым конкурирующим источником категории. При переносе один однозначный старый вариант можно сопоставить через UID варианта и категории; несколько тем, конкурсы и неоднозначные случаи требуют разбора, а не выбора по первому значению. Общая лента не теряет неклассифицированные публикации.

### Выдача и инфографика

- Общая лента и выбор категории работают с одними опубликованными записями; фильтр передаёт UID категории, не название или имя пиктограммы.
- Справочник отдаёт id, title_ru, short_title, description, color, icon, sort_order и is_active. Новость возвращает UID своей категории и её представление либо использует тот же загруженный справочник.
- В фильтрах, списках, карточке новости и пульте робота используются одинаковые цвет, пиктограмма и подпись. Отдельных захардкоженных палитр по экранам не должно быть.
- Внутри категории сохраняется порядок по времени выхода новости, новые сверху. Смена фильтра начинает пагинацию заново; фильтрация выполняется до лимита страницы.
- Цвет сопровождается пиктограммой и текстом. Фон остаётся нейтральным. Существующие иллюстрации, графика и авторская композиция новости сохраняются.
- Отключённая категория сохраняет отображение у старых новостей; скрытие из выбора для новых записей не скрывает опубликованный архив.
- Изменение категории редактором не означает автоматический повторный запуск конвейера, перегенерацию текста или публикацию.

### Права, аудит, BackUp и реализация

Публично доступны только чтение справочника и опубликованные новости. Изменение справочника — su; назначение категории — по действующим правам редактирования новости, публикация — по отдельному праву publish. Поля авторства и времени обязательны в операциях приложения; изменение категории новости входит в её историю версий. Изменения оформления должны оставлять проверяемый след до/после в действующем механизме аудита; служебные поля сами по себе не являются полным журналом. Новый журнал применений БД этим проектом не объявляется реализованным.

При реализации: нумерованная миграция вперёд одной транзакцией; перед применением — проверенная копия по BackUp; сохранение прежних тем, версий, прав и оценок. Проверки: FK и недопустимые категории, права чтения/изменения, опубликованная категория против черновой, выборка и пагинация, сохранность старых новостей, единое оформление. Копия должна включать справочник, его права и связи; SVG-набор сохраняется с кодом. Эта запись не подтверждает backup, миграцию или выкладку.
