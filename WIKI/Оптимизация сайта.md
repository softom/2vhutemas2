# Правила оптимизации сайта

Приняты пользователем 2026-09-27: «Запиши все решения, необходимые для оптимизации сайта, в WIKI как правила». Правила собраны из решений [Р-65](Решения.md) (поисковики и цитирование), [Р-66](Решения.md) (Метрика), [Р-68](Решения.md) (изображения — цитаты) и ответов пользователя в тот же день. Правило — это то, что проверяем при каждой правке сайта; подробности и причины — в решениях. Общие правила проекта — [Правила проекта](Правила%20проекта.md), правило 21 ссылается сюда; правило 20 там же — об изображениях-цитатах.

## Страницы

1. **Поисковик получает готовый HTML.** Любой публичный адрес отвечает страницей с содержанием, а не пустой оболочкой: заголовок, описание, основной текст, ссылки. Готовую страницу собирает API по запросу (`api/src/routes/pages.ts`), а не пререндер при выкладке: запись публикуют без выкладки, и поисковик должен увидеть её сразу. Новая публичная страница клиента без готового HTML — недоделка.
2. **Один шаблон на весь сайт.** Всё общее для страниц — счётчики, значок, метатеги по умолчанию — ставится в `web/index.html`. Из него собирается клиент, в него же API вкладывает готовые страницы; второго места для общего кода нет.
3. **У каждой страницы — свой заголовок и описание.** Заголовок: «Название — 2ВХУТЕМАС». Описание: первый абзац текста, до 200 знаков, по границе фразы. Одинаковых описаний у разных страниц быть не должно.
4. **Каждая публичная страница размечена.** `canonical`, `og:title`, `og:description`, `og:locale`, `og:image` при наличии открытого изображения, JSON-LD schema.org по виду записи (здание, произведение, человек, организация, лекция) и хлебные крошки. Разметка описывает только то, что видно на странице.
5. **Тексты «О проекте» — в одном месте, `web/src/about/texts.tsx`, и в готовой странице целиком.** Клиент рисует их оттуда; при сборке (`npm run build`) те же компоненты превращаются в HTML (`src/about/prerender.tsx` → `dist/prerender/about.json`), и API вкладывает его в `/about/{раздел}`. Копий текста в API нет. Пустой фрагмент останавливает сборку. В `texts.tsx` — только разметка без состояния и браузера; интерактивное (конструктор, обложка) остаётся в `About.tsx`. **Описание для выдачи** — фразы из самого текста подраздела, а не пересказ: суть лежит в `ABOUT` в `api/src/routes/pages.ts`, правка текста правит и её. Манифест — авторский текст (Р-67): в описание идут только его фразы. Новый подраздел без записи в `ABOUT` отвечает поисковику 404.
6. **Рабочие экраны закрыты от индекса.** Вход, медиатека, параметры, создание и правка записи — `noindex` и запрет в `robots.txt`.

## Адреса

7. **Постоянный адрес записи — `/entities/{slug}`.** Номер записи и прежний слаг ведут на него кодом **301**. Карточка не «переезжает»: смена слага не ломает ни одной выданной ссылки ([`slug_history`](Структура%20БД.md)).
8. **Несуществующее отвечает настоящим 404.** И неизвестный адрес, и неопубликованная запись: код 404 от сервера и «Страница не найдена» на экране, а не переброс на главную. Номер черновика не перенаправляется — редирект выдал бы его слаг.
9. **Внутренние связи — по-прежнему по UID** ([правило 1](Правила%20проекта.md)). Слаг — адрес для людей и поисковиков, а не ключ: в текстах и связях лежат номера записей.

## Служебные файлы и поисковые системы

10. **`robots.txt` и `sitemap.xml` строятся из данных.** В sitemap — только опубликованные записи с датой последней правки записи или её текста. Руками эти файлы не правятся.
11. **Файлы медиатеки открыты для обхода** (`Allow: /api/v1/media/`), остальное API — закрыто. Индексацию картинок отдельно от текста регулирует API заголовком `X-Robots-Tag: noimageindex` на выдаче файла (Р-68); в Caddy его не дублировать.
12. **Публикация сообщается поисковикам сразу** — IndexNow в Яндекс, если в настройках API задан ключ. Неудача уведомления пишется в журнал и публикацию не держит.
13. **Прежний сайт `/old` закрыт от индекса целиком** заголовком `noindex` в Caddy. *Решение пользователя 2026-09-27: посещаемость старого сайта нулевая.* В `robots.txt` `/old/` не закрывается: иначе поисковик не увидит `noindex`.

## Цитируемость

14. **У каждой записи — «Как цитировать».** Ссылка по ГОСТ Р 7.0.100–2018 и в APA с постоянной ссылкой и датой обращения. Текст ссылки считает одно место — API (`citation` в карточке), и клиент, и готовая страница берут его оттуда.
15. **Источники видны и ведут наружу.** Ссылки на Wikidata и Википедию среди источников записи становятся `sameAs` в разметке; отдельных полей для них не заводим ([правило 14](Правила%20проекта.md)).
16. **Обоснование связи выводится открытым текстом** рядом со ссылкой — и в клиенте, и в готовой странице. Это собственный текст проекта, которого нет в энциклопедиях.

## Изображения

17. **Изображение показывается как цитата в учебных целях; автор и источник — задача редактора, а не условие публикации** ([Р-68](Решения.md), [правило 20](Правила%20проекта.md)). *Первоначальный запрет публиковать файл без подписи пользователь ослабил в тот же день: «важна целостность сайта».* Незаполненные ссылки видны в медиатеке списком; признак один на систему — `app.media_needs_attribution(a)`, условие не переписываем.
18. **Подпись идёт всюду, где идёт картинка и где она известна:** «Автор · Источник» под изображением в клиенте и в готовой странице, `creator`, `creditText` и `isBasedOn` в JSON-LD. Пустых подписей и пустых полей разметки не выводим. Внешняя картинка (чужой адрес в тексте, не файл медиатеки) без подписи в готовую страницу не попадает.
19. **Картиночная индексация закрыта** (`noimageindex` на выдаче файлов, правило 11): изображения показываем читателю, но в поиск по картинкам не отдаём.

## Видимость и аналитика

20. **Гость видит только опубликованное** — и связи тоже: связь с черновиком гостю не показывается, иначе название черновика утекает через соседнюю карточку.
21. **Счётчик Яндекс.Метрики (108525511) — на каждой странице** через общий шаблон (правило 2). Переходы внутри сайта засчитываются отдельно (`App.tsx`), замена адреса номера на слаг новым просмотром не считается. На `/old` счётчика нет.
22. **152-ФЗ отложен.** Политика обработки персональных данных и уведомление о cookies для Метрики пока не делаются — *решение пользователя 2026-09-27: «давай пока оставим»*. Вернуться к вопросу до того, как на сайте появятся формы для посетителей или регистрация студентов.

## Порядок и проверка

23. **Порядок включения** (пользователь, 2026-09-27): выкладка Метрики и Р-68 (миграция 0021 закрывает неподписанные файлы) → проверка Метрики в кабинете → публикация всех записей (*решение пользователя: «Публикуем все»*) → настройка сервера по [Инвентаризации](Инвентаризация%20сервера.md) и выкладка SEO → Яндекс.Вебмастер и Google Search Console с отправкой `sitemap.xml`. Звать робота раньше публикации — звать его на пустой сайт.
24. **Прогон проверяет SEO снаружи, через Caddy:** готовая страница записи, canonical, JSON-LD, «Как цитировать», 301 с номера на слаг, sitemap, robots, 404, `noindex` на `/old`, счётчик Метрики. Падающая проверка SEO не снимается ради зелёного прогона — она напоминает о несделанном.
25. **Падение API не кладёт сайт.** При 502–504 Caddy отдаёт статический клиент. Проверяется при настройке сервера остановкой контейнера API.
