# Новости — разделы промпта и причины оценки

Основание: пользователь поручил разделить текущий промпт, подавать новости в блоке 3 по категориям и дифференцировать «Выпустил бы» на причины.

Промпт разделён на общие правила, категорию/событие (2.1), новизну/актуальность (2.3), ценность по категории (2.4), формат и примеры/контракт ответа. Профиль состоит из общих правил и шести разделов. Проверены 14 правил действующего серверного профиля: исходные формулировки сохраняются и распределяются по разделам. Известные старые строки распределяются точно; неизвестный авторский текст остаётся в общих правилах для ручного уточнения. Для материалов сайта и искусствоведения недостаток прежних примеров явно указан в профиле по умолчанию; калибровке запрещено выдумывать предпочтения. Действующий обученный профиль не затирается профилем по умолчанию.

Интерфейс классификатора редактирует отдельно разделы профиля и шаблона. Старый произвольный текст и неизвестные заголовки сохраняются. При сохранении используется прежний контракт API с полным profile_text/triage_template; placeholders сохраняются.

В редакторе — шесть фильтров и заголовки категорий в общей выдаче. Новая оценка содержит логический атрибут category; старые кандидаты получают переходное отображение по прежним topic/kind/competition. Конкурс приоритетнее темы; исследование ИИ остаётся в ИИ; неизвестные — «Без категории». Это не реализация справочника app.news_categories и не FK на строковый код: новых таблиц/колонок БД нет, опубликованные новости не переклассифицируются.

«Выпустил бы» раскрывает причины соответствующей категории и собственную причину редактора. Выбранная причина сохраняется как отдельный явный довод в существующем JSON-контракте claims, с названием категории, и включается в примеры/калибровку. Неотмеченные доводы остаются неоценёнными и в UI, и в нормализации Python. Действие «В стек» отделено. Отказ, проверка сомнений и причины момента сохранены; исторические записи не пересчитываются автоматически.

Для сквозной передачи доводов использованы ранее подготовленные локальные изменения API, типов, UI, discover/learn/pipeline. Они включены в коммит как необходимая основа текущей функции; отдельные прежние изменения run.py/pool.py и прочие пользовательские правки не включены. Постоянный неизменяемый журнал решений всё ещё не реализован: нынешняя запись judgment по story_key перезаписывается. Разделение текста промпта ещё не означает независимые вызовы LLM или отдельные калибровки шести конвейеров. Старый итоговый interest/rank сохранён для совместимости.

Проверки: TypeScript; сборка Vite; пять Python-тестов (сохранность и идемпотентность разделения профиля, приоритет категорий, отсутствие автоматического подтверждения доводов, запись причины/категории, отделение давности от вкуса); браузер с тестовым API (группы/фильтр, причина в payload, неоценённые доводы, сохранность других разделов и placeholders). Выкладка фиксируется отдельной записью после проверки. Массовая переоценка и платные LLM-вызовы в рамках проверки не запускались.
