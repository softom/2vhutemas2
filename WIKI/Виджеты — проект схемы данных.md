# Виджеты — проект схемы данных

Предложение для обсуждения 19.11.2026. Действующий settings.card_widgets описан в [[Виджеты карточки — контракт]]. Ниже целевая модель; перенос существующих настроек требует отдельной сверки.

| Хранилище | Назначение |
|---|---|
| widgets | UUID определения, название для автора, уникальный ключ реализации в коде. Допустимые размеры, поддержка дизайнов и обязательность входа задаются контрактом реализации. |
| widget_layouts | UUID макета; для повторяемой выборки — UID типа сущностей и правило сортировки с UID сущности последним критерием. Первый вариант поддерживает одну выборку на макет. |
| widget_layout_items | UUID места, layout_id и widget_id (UUID FK), порядок, колонка и строка внутри образца, ширина и высота в ячейках, необязательный вариант дизайна. В шаблоне карточки вход — UID карточки; в повторяемой выборке — UID очередного результата. |
| type_presentations | Необязательный layout_id для режима card. Сохраняется выбор ближайшего представления по дереву типов. |
| Страница каталога | Устойчивое назначение макета странице раздела. Если страница представлена сущностью, привязка по entities.id; для программного маршрута — явное назначение UID макета в конфигурации маршрута. |
| Блок widget в blocks_value | UID определения, необязательный UID входной сущности и вариант дизайна в теле существующей версии документа. Проверка ссылок при сохранении/публикации, запрет удаления используемого определения, включая ссылки из сохранённых версий. |

Для новых таблиц — FK по UID, целые положительные размеры, границы трёх колонок и проверка пересечения мест одного образца. Индекс строки относительный, строки повторов и результаты выборки не материализуются. У одного определения может быть сколько угодно вставок. Старые определения сохраняются для чтения опубликованных материалов.

Параметры предметных данных уже поддерживают number, integer, text, boolean, option, date, entity, blocks, table. Сущность на входе имеет тип существующего entities.id (bigint); это не UUID определения виджета. Раскладка и код не являются значениями показателей. Игровой материал, если его нужно редактировать, можно хранить как сущность с набором параметров и версиями. У игры «Стили» сейчас подбор и ответы в генераторе, сведения о зданиях загружаются по ID, счёт живёт в сеансе. Перенос в компонент должен сохранить авторский состав и правила. Хранение попыток и результатов в БД — отдельная возможность при появлении требования.
