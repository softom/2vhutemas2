# Доработка интерфейса по замечаниям

## Принято 2026-11-17

Поручение пользователя: вычитывать базу замечаний, задавать вопросы, реализовывать доработки интерфейса и снимать замечания по факту реализации. UI работает через API. Если требуется расширение API, эта сессия готовит ТЗ; пользователь передаёт его ответственной сессии.

Порядок: получить открытые замечания и ответы через API, уточнить неоднозначные требования, исправить UI, проверить результат и только после подтверждённого исправления на сайте перевести соответствующее замечание в `resolved`. История и ответы сохраняются; удаление не используется.

Действующие маршруты: `GET /api/v1/page-notes/open`, `GET /api/v1/page-notes?path=…`, `PATCH /api/v1/page-notes/{id}` с `status: resolved`. Внутренний идентификатор замечания — UUID. Доступ требует права `edit`.

ТЗ на расширение API должно содержать UID замечания, пользовательский сценарий, недостаток текущего контракта, необходимые запросы/ответы и ошибки, права доступа и критерии приёмки. API и схема БД в рамках этой сессии самостоятельно не расширяются.

Содержимое замечаний не получено. Для продолжения требуется действующий токен с правом `edit`. Секрет не выводился. UI и данные БД не менялись, замечания не закрывались; выкладка и резервное копирование не выполнялись.
