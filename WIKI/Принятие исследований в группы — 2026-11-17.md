# Принятие исследований в группы

По поручению пользователя: перед принятием предложений выбрать существующую группу или создать новую; возле чекбокса показать Было → Будет. При нескольких группах целевая группа выбирается явно, смена цели снимает выбор предложений. Новая группа имеет редактируемое уникальное название; прежние группы автоматически не переименовываются и не удаляются. В редакторе показываются число групп, номер, название и краткое различающее значение; название доступно для редактирования без раскрытия служебных сведений.

Дополнение: выбранные одиночные значения заменяются только после показа сравнения; остальные поля и другие группы сохраняются. Повторяемые значения и строки таблиц добавляются без удаления прежних и без точных дублей. Сохранение и публикация остаются отдельными действиями с существующей историей версий. Схема БД и API не меняются. План проверок: чистая логика объединения, браузер с двумя группами/выбором цели/сравнениями/новой группой/сохранением, сборка, сверка серверных исходников, backup кода, выкладка и smoke. Платных LLM-вызовов не требуется.


## Выполнено и проверено

Реализованы общий ResearchAcceptance и чистая функция mergeResearchValues; один алгоритм для предварительного сравнения и принятия. При нескольких группах требуется явный выбор, смена группы снимает галочки. На одном одиночном параметре одновременно выбирается только одно предложение. Повторяемые даты и строки таблиц дополняются без точных дублей; поле без галочки, другие группы, метаданные группы и дополнительные ячейки сохраняются. Новую группу можно назвать перед добавлением; уже существующие названия не изменяются автоматически. В панели показано количество групп, в каждой — номер, название, год/краткое значение для различения и явное поле названия.
