USE_WIDGET_LAYOUTS по умолчанию false; для тестового включения процесс API получает значение true. ## Перенос

api/tools/migrateCardLayouts.ts выполняется из api под Deno с конфигурацией проекта, доступом к БД и UID действующего участника с su. Аргументы: имя БД, UID участника, --apply. Имя БД обязано совпадать с APP_API_DB_NAME. Команда одной транзакцией проверяет страницу карточки, регистрирует реализации секций и создаёт макеты из явных card-представлений. Существующее назначение сохраняется. Незнакомый компонент или неоднозначная запись card_widgets останавливают транзакцию с указанием типа. Старые строки секций и остальные настройки сохранены.

В исходной схеме type_presentation_items содержит строки секций. Для виджета «Параметры» порядок UID наборов записан в settings.parameter_set_ids существующей строки indicators. Уже заданный список сохраняется. Начальный состав рассчитан по наследованию, индивидуальным прикреплениям и членству параметров имеющихся записей. У каждого типа один слот параметров. Значения без набора остаются видимыми. Внутреннюю сторону определяет card_side. Индивидуально добавленный впоследствии набор должен входить в список представления для его показа в этом макете.

Созданы 12 назначений на **одной** странице карточки с пустым current_layout_id. У what слот параметров занимает колонки 1–2, у остальных 11 представлений — колонку 3. Повторный запуск сохранил все 12 UID. Остальные слоты следуют порядку имеющихся секций. В исходном снимке дополнительные card_widgets были пусты.

## Рендер и контроль

Реестр привязывает функции секций к уже загруженной разрешённой версии сущности. Гость получает только занятые слоты, редактор — в том числе «Нет данных». Сервер считает занятыми все строки, покрытые row_span. Геометрия БД не меняется. Браузерная сетка сохраняет декоративную полосу между второй и третьей логическими колонками, на узком экране слоты идут в порядке чтения. Узкие группы характеристик помещают значение под названием.

В тесте с настоящими тремя слотами (включая 2×2) гость получил два, редактор — три; в БД осталось три. Для 3121 проверен отдельный слот style_analysis: одна секция стилистики, без повтора внутри параметров. Для черновика 606 гостевой API вернул 404, редакторский — 200. Гостю предпросмотр копии запрещён (401), при выключенном флаге у редактора — 503.

Контрольные файлы находятся в локальной папке проекта **контроль/после-этап3/**. Там сохранены HTML до назначения, после назначения при обоих состояниях флага, гостевые снимки, авторизованные карточки, пять форм редактирования, мобильный кадр, отчёт сверки и SHA-256. Проверены UID 188, 3121, 238, 1432, 563. Сверены ссылки, URL изображений, подписи, ячейки таблиц, пары названий и значений, вложенные модели и цитирование. Для даты обращения учтён переход с 19 на 20 ноября. Исходные редакторские PNG изображали формы, поэтому дополнительно сняты и формы, и новый читательский вывод редактора. Изменение визуальной геометрии ожидаемо: в частности, обе группы параметров находятся внутри одного слота. На 390 px проверен одноколоночный порядок.

## Копия → предпросмотр → назначение → возврат

Проверено в Edge на изолированной базе через Hono с тестовым principal. Авторизованный маршрут /api/v1/entities/:key/card?preview_layout_id=<UID> принимает только макет страницы карточки и требует su. Предпросмотр не меняет назначение. Пользователь выбрал тип what, создал копию, изменил порядок, просмотрел карточку 188, назначил копию, затем вернул исходный макет. В audit_log сверены две взаимно обратные записи layout_assigned с автором. Контрольные данные — сценарий.json и аудит.txt. Рабочие аккаунты, назначения и материалы сайта в проверках не изменялись.
