# Незавершённая загрузка обложек — 18.11.2026

По скриншоту пользователя проверена передача файлов /objects, а не только первая отрисовка страницы. Исправления исходников и production в этой проверке не выполнялись.

В чистом Chromium через 6 секунд первые четыре img имели naturalWidth/naturalHeight, но complete=false; завершённых resource timing для медиа ещё не было. Это подтверждает частичную передачу изображений, а не отсутствие публикации или пустые данные. Следующий запуск загрузил первые четыре обложки примерно за секунду: проблема непостоянна.

Проверка одного и того же опубликованного файла:

- Махорка, asset 101cc509-5d4a-4a35-95be-717ecc03bc57, screen: 262784 байта, HTTP 200. С рабочего компьютера первый байт 0,864 с, весь файл 11,555 с. На сервере через тот же публичный HTTPS: первый байт 0,163 с, весь файл 0,164 с.
- Friendship Centre, asset d01ef562-4274-493e-9403-48f0e4e98020, thumbnail: 27624 байта, HTTP 200. С рабочего компьютера первый байт 0,786 с, весь файл 0,826 с; на сервере весь файл 0,179 с.

Код выдаёт уже подготовленные screen/thumbnail, без преобразования при запросе. Публичные файлы имеют public,max-age=86400. В каталоге используется screen для первой плитки и thumbnail для остальных; исходные фотографии вместо миниатюр не запрашиваются. CSS object-fit=cover; размер крупного производного изображения 1600×1062, миниатюр обычно до 400 пикселей.

Вывод: в медленном измерении основная задержка была после первого байта при передаче файла клиенту. Быстрая серверная проверка исключает длительную генерацию этого файла в данном запросе; она не доказывает точную причину сетевой деградации. Причина нестабильности (маршрут, соединение/протокол, прокси или иной промежуточный участок) не установлена. Сравнение отдельного HTTP/1.1 запуска с другим обычным запуском не является достаточным доказательством дефекта HTTP/2.

Не объявлять проблему исправленной и не считать FCP/DOMContentLoaded проверкой готовности обложек. Дальнейшая проверка должна фиксировать complete/naturalWidth и завершение передачи первых обложек в нескольких холодных запусках; для выбора сетевого исправления нужны сопоставимые замеры в момент замедления.
