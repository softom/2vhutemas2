Описание API

Через API внешняя система может читать опубликованные карточки, передавать материалы на рассмотрение и редактировать существующие карточки. Базовый адрес — https://2vhutemas.ru/api/v1.

Проверка токена

Администратор выдаёт токен на 1, 7, 30 или 90 суток и выбирает права. Передавайте его в заголовке Authorization: Bearer <токен>. В примере переменная окружения API_TOKEN содержит выданный секрет.

curl -H "Authorization: Bearer $API_TOKEN" https://2vhutemas.ru/api/v1/me

В ответе token_id обозначает UID токена, display_name — имя системы, permissions — массив выданных прав, expires_at — время окончания действия с часовым поясом. Запрос без заголовка возвращает authenticated: false.

Приём материалов

POST /incoming-materials требует права intake. Отправьте JSON с заголовком Content-Type: application/json. Назначьте досье и каждому источнику отдельный UUID. Ниже пример тела запроса.

{
  "id": "a95ff5bc-c904-4507-82c8-90f79bcf5413",
  "title": "Описание архитектурного проекта",
  "sources": [{
    "id": "ec9aa64d-0eaa-4bde-9b22-609904e668e2",
    "title": "Страница проекта",
    "url": "https://example.org/project",
    "media": []
  }]
}

Используйте новые UUID для нового материала. При повторной отправке того же досье сохраните его UID и используйте тот же токен. Успешный ответ — HTTP 201 и поле id. Досье поступает на рассмотрение со статусом «Предложено».

Создание карточки

При выдаче токена выберите «Создание карточек». Проверьте, что GET /me возвращает create_cards в массиве permissions. Чтобы затем читать и править созданный черновик, выберите также «Редактирование карточек» (edit_cards).

Для POST /entities укажите код типа, уникальный адрес slug и русское название. Пример создаёт черновик метода формообразования:

curl -X POST https://2vhutemas.ru/api/v1/entities \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"form_method","slug":"example-form-method","title_ru":"Пример метода"}'

При успехе API возвращает HTTP 201, числовой id карточки, material_id и revision_id первой версии. Для публикации требуется отдельное действие участника с правом публикации.

Чтение и редактирование карточек

Без токена GET /entities возвращает каталог опубликованных карточек, а GET /entities/{id} — одну карточку. В адресах ниже {id} означает числовой UID сущности.

  1. С токеном, имеющим право edit_cards, вызовите GET /entities/{id}. Сохраните latest_revision_id из ответа.
  2. Отправьте PATCH /entities/{id} с тем же токеном и типом содержимого application/json. В поле base_revision_id подставьте сохранённый UID версии. Для изменения названия тело выглядит так: 
    {
  "base_revision_id": "<latest_revision_id из GET>",
  "title_ru": "Новое название"
}
  3. В успешном ответе получите revision_id. Повторным GET проверьте изменения и номер рабочей версии. Публикация выполняется отдельно участником с правом публикации.

Создание связей

При выдаче токена отметьте «Создание связей». В ответе GET /me появится право create_links. Чтобы связать две существующие карточки, отправьте их числовые UID и обоснование на POST /links. Подставьте UID своих карточек и текст, объясняющий связь.

curl -X POST https://2vhutemas.ru/api/v1/links \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"from_entity_id":101,"to_entity_id":102,"justification":{"text":"Автор указан в проектной документации."}}'

HTTP 201 возвращает id связи, material_id и revision_id первой версии. Связь создаётся как черновик. Публикация, изменение и удаление связи требуют отдельных полномочий.

Ошибки

401 — ошибка авторизации
Проверьте заголовок и срок действия токена через /me.
403 — недостаточно прав
Сверьте permissions с правом, которое требуется для операции.
409 — конфликт версии при правке
Перечитайте карточку, сверьте новые изменения и повторите запрос от актуальной версии.
