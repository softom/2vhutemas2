# Наполнение 2vhutemas

## Контекст и готовность

Читай [контракт API](../../WIKI/API.md) и нужные разделы [модели данных](../../WIKI/Структура%20БД.md). Они являются источником требований проекта.

На момент создания навыка API v1 — проект, рабочего клиента ещё нет. Пока нет проверенного API, готовь локальный план записей, источников и зависимостей; явно сообщай, что данные не загружены. Не подменяй API прямой записью SQL и не угадывай работающие маршруты по проектной таблице.

Когда API доступен, проверь его контракт и capabilities перед записью. Используй предоставленный для нужного окружения ограниченный токен, не выводи его в файлы, отчёт или командную строку. Если нет контракта, доступа или совместимости схемы, заверши доступную подготовку и обозначь конкретный блокер.

## Преобразование материалов

- Найди существующие сущности перед созданием. Совпадение названия не доказывает идентичность; различай здание, постановку, событие и организацию.
- Сохраняй подтверждённые источники. Неизвестные даты и авторов оставляй неизвестными. Авторская интерпретация хранится с её автором и пояснением, не становится фактом автоматически.
- Связь создавай только атомарной операцией с непустым описанием-обоснованием. Упоминание объекта в лекции является ссылкой документа и не требует создания links.
- Изображения связывай с происхождением и атрибуцией; загружай оригинал. Производные создаёт медиасервис. Не выдавай превью за высококачественный исходник.
- Лекции готовь как BlockNote JSON по действующей схеме: устойчивые ID блоков/вхождений, entity_id для карточек, asset_id для медиа. Сохраняй авторский порядок и локальные пояснения, не копируй объекты ради повторного появления.
- Правки существующих материалов основывай на прочитанной версии. Сохраняй неизвестные блоки; несовместимый формат не упрощай до Markdown с потерей оформления.

## Запись и проверка

Используй validate и apply по контракту. Для зависимостей сохраняй локальные ключи и полученные ID. Повторяй запрос после неопределённого результата только с тем же ключом идемпотентности и телом; сначала прочитай состояние операции. При 401/403 прекрати запись, при конфликте перечитай версию и не затирай изменения. Предел попыток временных ошибок бери из automation.retry.max_attempts в [параметрах проекта](../../WIKI/Параметры%20проекта.md), учитывай Retry-After; не повторяй успешные элементы пакета.

Следуй объёму пользовательского запроса: наполнение не разрешает назначать роли, удалять старые материалы или публиковать черновики без указания на это. Не добавляй повторные запросы разрешения для уже согласованного наполнения.

После применения прочитай созданные записи и проверь ссылки, версии, авторство и состояние медиа. Сообщи, что создано/обновлено/пропущено, укажи доступные адреса и ID, нерешённые совпадения и ошибки. Не объявляй загрузку завершённой при частичном сбое или незавершённой обработке медиа.
